06 · 多信号源上传与硬件接入说明

需求编号 7008111111《基于对话内容的行为异常检测和心理变化分析技术》。 本篇回答三件事：这一版能收哪几路信号、每一路的结论上限写在哪里、后续硬件还能接什么。 对应实现：prototype-lite/ 工作台离线链路，界面见 03_精简版界面可视稿.html 第 06—13 幅（实拍）。

一、口径先说清：这一版做到哪一步

招标 28.01 原文："不限于语音、视频、近红外、毫米波等单一或多种信号的输入"。 "不限于"和"等"是开放表述，所以本条目要交的不是"接了四个传感器"，而是一套能容纳多路异构信号、并且每一路都能说清自己贡献与上限的输入框架。

维度本版（文件级多路登记）本版不做（属后续硬件接入项）
输入形态上传素材文件：视频 / 音频 / 近红外采样序列 / 毫米波采样序列硬件在线接入、驱动、采集盒常驻
必填性音视频为主（任一即可起批）；扩展信号多选、非必填—
参与度登记后每一份都进入批分析，逐份切片、逐份列示，不因未勾选而被跳过—
时基按素材登记时长对齐到脚本时轴（分钟级）采样级时钟同步（PTP/NTP）、跨设备触发对齐
标定以素材静息段为中位数基线，出相对升幅个体基线标定、跨会话个人基线库
结论音视频走完整三级归因；近红外 / 毫米波只到生理趋势层扩展信号进入升级、进入心理归因

一句话：把"多信号输入"从形容词变成动词——多路文件可登记、可分析、可出报告，同时每一路的结论上限在代码、界面、报告三处写死。

二、四类素材 × 六类异常：谁能提供哪一路

六类异常口径（28.07）：言语表达、语音特征、身体姿态、手部动作、面部表情、生理指标。 系统内部固定为六路模态键 voice / semantic / face / pose / hand / physio，不因新增信号源而扩键——近红外与毫米波都归 physio，但走独立的封顶链。

素材类型可解析模态不可解析模态是否进脚本判定链结论上限本版状态
视频（主信号）语音·语义·表情·姿态·手部·生理(rPPG) 六路无是可出三级归因、可触发升级已实现
音频（主信号）语音·语义表情·姿态·手部·生理是可出三级归因；缺的四路不产出 0 值，整条判定不产出该项已实现
近红外（fNIRS 口径的采样序列，扩展）生理其余五路否只到生理趋势层：趋势 + 单模态异常，候选规则层恒为空，不进 ESCALATED已实现（文件级）
毫米波雷达（扩展）生理其余五路否同上；质量降级时趋势仅供复核已实现（文件级）

三条实现约束（评审时最容易被追问）：

  1. 可用性由素材类型决定，不由人勾选。 界面上没有"要不要分析表情"的开关；只有素材。缺的那一路在结果页显示 ✕，在报告里显示"不可用"，在 CSV 里不出行——避免"没测"被读成"正常"。
  2. 同一路信号可以有多个文件（两台摄像机、前后两段采样），按 文件名 + 类型 去重登记；每条主信号异常标出承载素材清单，报告第四节逐条写明"·素材 A/B"。
  3. 融合发生在会话层，不发生在素材层。 每份素材各跑自己的解析链（切片），最后在会话层用与实时监看同一套判定函数聚合，判定口径在报告首节写明 E1 融合 + E2 判定（与实时监看同一函数）。

三、扩展信号为什么封顶：逐条独立失效原因

一个失效原因占一行，且给出现场可执行判据——不写"精度不足"这类无法核对的话。

#失效 / 限制原因现场怎么判断这一路能不能采信代码里的落点
1近红外测的是前额血氧相对变化，不是神经电活动，空间只能覆盖表层是否采到静息段；探头—源距是否在 25—30mm 光程经验区间cap_note 逐条列出，报告附表 A「结论上限」列
2头动伪迹与激活信号同为血氧浓度变化，置 0 会读成"无激活"，不置 0 会读成"有激活"头动占比峰值是否 < 20%（超判据即整片标"降级"）quality='degraded' + 解析步骤 #3
3毫米波呼吸/心率是从体动杂波中反演的，对象靠近、说话、翻身都会退化体动幅度峰值是否 < 8mm同上，mmwave 判据独立于 nir
4文件级导入没有共同时钟，跨信号对齐只能到分钟级素材登记时长是否与元数据一致（不一致时结果页标"时基未读出"）PhysioTrend.time_base 显式声明取哪一时基
5无个体基线标定，绝对值不可比只看相对静息段（前 25% 采样窗）升幅，不看绝对浓度/绝对 bpmbaseline 取静息段中位数
6近红外与视频 rPPG 是两个不同估计量，数值接近不构成互相校验演示脚本里两路共用一条唤醒度基线，所以曲线同形；真实设备上两路误差不相关报告「精度受限」提示块逐字写明

自定义口径的诚实标注（出处目录 C 级）：显著性判据为"峰值相对静息段中位数升幅 > 12% 且末段 6/10 窗维持升幅 60% 以上"；confidence 在该层被重定义为趋势显著性的折算值，不是归因置信度。这两条是本方案自定，不引文献，报告与结果页同时写出，供评审直接否。

四、后续硬件接入的候选信号源（四组）

分组依据是接入代价与口径影响，不是设备热度。

A 组 · 只差驱动与时钟，解析链已在本版就位

信号源归入哪一路接入代价主要失效原因
近红外（HbO / HbR 采样序列）physio（扩展链）厂商 SDK → 采样序列落盘，接口不变（文件级本版已跑通）头动、光程耦合不良
毫米波雷达（呼吸/心率）physio（扩展链）同上体动杂波、多目标串扰
USB 麦克风阵列voice需通道选择与增益标定远场混响压低 jitter 估计质量
网络摄像机 RTSPface / pose / hand需拉流与抽帧节流压缩伪迹、帧率抖动破坏 AU 时序

> 本版口径（一句话）：我们支持近红外 / 毫米波这类采样序列文件的导入与分析——文件能登记、能切片、能进报告，本版已按此实现；结论封顶在生理趋势层。 > 硬件直采走哪条技术路线（反射式成像还是采集盒）是硬件方案的事，不在本版承诺范围内；本版只做到"收到文件就能算、算到哪一步写清楚"，接口对后续硬件保持不变。 > 对需求方就一句：「这一版把'能收哪些文件、收到后怎么算、算到哪为止'做实了，硬件接入是下一步。」

B 组 · 需新增一路模态定义，会撑破"六类"口径 → 先与需求方确认再接

信号源归入哪一路为什么先确认
皮电 EDAphysio唤醒度可用，但受温度/湿度/电极凝胶影响，且招标六类里没有独立条目
皮肤温度physio变化周期以分钟计，与对话窗口不同尺度
单导联心电 ECGphysio与 HRV 同源但需贴附，谈话场景接受度需评估
呼吸带 / 胸腹带physio与毫米波呼吸通道重复，重复即冲突源

C 组 · 不建议接入（关联弱或合规风险高）

信号源不接的理由
脑电 EEG需医疗/科研资质与专业贴附，伪迹主导，与"对话内容行为异常"的因果链过长
桌面式眼动仪部署形态冲突（要求头部约束），外勤与谈话室均不适配
消费级"情绪指数"手环厂商黑箱指数无法拆到观察层，违背可解释归因主线
任何以"测谎"为卖点的传感器线索效应量级不支持结论性判定，且与本系统"输出风险提示、非临床诊断"的免责口径直接冲突

D 组 · 接入形态（工程侧）

传感器 / 采集盒 →（USB·串口）边缘网关 →（PTP/NTP 统一时基）→ 采样序列落盘为文件 → 本版同一条登记链。 关键点：硬件接入不改判定接口，只改时基与标定。本版按文件级导入实现的切片、封顶、报告列示，在硬件接入后仍然成立；届时新增的是"在线通道"与"时钟源"两件事，扩展信号的结论上限（只到趋势层）是否放开，取决于个体标定是否落地，而不是取决于设备是否在线。

断言断的是什么
四份素材各产出一片切片"上传后所有文件都参与分析"不是话术，切片数 == 登记数
每片可用 + 不可用模态恒为 6缺的路不产出 0 值

每条主信号事件标出承载素材多文件可追溯

CSV 含 asset 列、扩展行标 trend_only（不出归因）导出件保留上限口径
导出 HTML 含「附表 A」与「离线导入 · 非实时」下载/打印件同样保留
仅扩展信号时判定链逐条裁撤并给原因、可用模态为空没有音视频输入时不冒充"检测正常"
未登记素材起批 422没有输入就不出结果

七、如实披露（本版本未实现项）

  • 判定为演示脚本回放，未接入真实 ASR / 视觉 / rPPG / 传感器推理；扩展信号趋势曲线由脚本唤醒度基线派生，不构成跨信号校验证据。
  • 采样序列文件按"读首列推时基、行数即样本数"登记，未做列名语义解析与单位换算；正式实现需补列映射配置与厂商模板。
  • 近红外 / 毫米波为文件级导入，非硬件在线接入；无时钟同步、无个体标定。
  • 导出件为明文 HTML，SM4 封装未实现（沿用完整版同一披露口径）。
