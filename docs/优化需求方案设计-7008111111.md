## 1. 现状诊断：原型哪些是真实的，哪些不是

现有精简版原型（`prototype-lite/`）验证了产品形态、交互闭环与数据契约，但**分析能力全部为脚本回放**，没有任何真实推理：

| 环节 | 现状 | 证据 | 目标 |
|---|---|---|---|
| 素材读取 | ✅ 真实（浏览器读时长/CSV 行数） | `SessionsPage.tsx:9-29` | 保持，扩展 WebRTC 采集 |
| 分角色转写 | ❌ 逐句硬编码（含 diar_conf） | `mock/script.ts:21-35` | FunASR + CAM++ 真实 ASR/分离 |
| 异常检测 | ❌ EV-001~007 及时间戳全部预设 | `mock/script.ts:65-210` | 各模态真实检测器 + 规则引擎 |
| 分析引擎 | ❌ 按时钟补发脚本事件 | `mock/engine.ts:1233-1348` | Python 真实推理服务 |
| 扩展信号 | ❌ CSV 仅数行数 | `SessionsPage.tsx:9-19` | 真实解析（滤波/谱峰/HbO-HbR） |
| 心理归因 | ❌ 模板文案 | `mock/script.ts` 内嵌 | 规则库 + 私有化 LLM 叙述组装 |

结论：**UI、数据契约、报告链路、审计留痕可直接复用；分析引擎整体替换。**

## 2. 设计目标与交付边界（方案 B，已确认）

- **音视频双模态全真实**：ASR/分角色/声学特征/表情 AU/姿态/手部/rPPG 全部真实算法运行。
- **扩展信号文件级真实解析**：毫米波（RR/HR）、近红外 fNIRS（HbO/HbR）从采样序列文件真实计算，结论封顶生理趋势层（沿用原型合规口径，不进心理归因）。
- **单一分析管线**：WebRTC 活体采集 → 落盘 → 自动触发与文件导入**同一条**离线批分析管线；采集端只做预览（画面/电平/时长），不做实时判定（需求无实时性条款）。
- **硬件在线接入留接口契约**：毫米波模组（MR60BHA2 级 UART/JSON）与 fNIRS 厂商 SDK 的在线接入只定义契约，实测以文件级为准。
- **数据源**：
  1. 文件样例：`prototype-lite/public/demo/` 四份对齐样例（录像 156s / 录音 156s / 毫米波 CSV 152s / 近红外 CSV 152s）；
  2. WebRTC：本机摄像头 + 麦克风活体采集（`getUserMedia` + `MediaRecorder`）。
- **许可原则**：全栈 Apache-2.0 / MIT / BSD，零授权费（避开 openSMILE 商用禁令、OpenFace 2.0 CMU 版税、Ultralytics AGPL 三个雷区，见 §11）。
- **合规口径**：非临床诊断声明在界面/报告/导出三处写死；所有心理原因为模型推断，必带反事实与免责；量化指标只给「文献参考水平 / 现场标定」两类标签。

## 3. 总体架构

**核心原则：契约不变，引擎替换。** 现有前端的 REST/WS 契约、页面结构、报告与审计链路零改动；Python 分析服务实现与 mock 插件**完全相同的契约**，mock 引擎退役为契约参照。

```
┌─ 采集层 ──────────────────────────────────────────────┐
│  A. 文件导入（mp4/m4a/csv，现有四登记区）                │
│  B. WebRTC 采集（getUserMedia+MediaRecorder → 落盘）   │
└──────────────┬─────────────────────────────────────────┘
               ▼
┌─ 分析服务（Python 3.11 / FastAPI，单机 GPU worker）─────┐
│  0 预处理  FFmpeg 解封装/抽轨/统一 16kHz WAV + 25fps 帧  │
│  1 语音链  FunASR(VAD+ASR+标点) + CAM++ 分角色 + 对齐    │
│  2 声学链  parselmouth/librosa 特征 + 个体基线 z-score   │
│  3 语义链  BERTopic+bge-m3 话题 / Erlangshen-NLI 矛盾   │
│  4 视觉链  SCRFD+ByteTrack → FaceLandmark/RTMPose/Hands │
│  5 rPPG    rPPG-Toolbox POS/CHROM（人脸 ROI）           │
│  6 扩展链  毫米波带通+谱峰 / fNIRS MBLL（趋势层封顶）    │
│  7 融合    E1 事件融合 + E2 规则判定（决策级，时间窗对齐）│
│  8 归因    规则库(L2→L3) + Qwen2.5-7B 叙述组装(RAG)     │
└──────────────┬─────────────────────────────────────────┘
               ▼  同一 REST/WS 契约（/v1/*，见 §8）
┌─ 现有前端（零改动）────────────────────────────────────┐
│  任务台 → 离线批分析进度(WS) → 结果/三级归因 → 报告审批  │
└─────────────────────────────────────────────────────────┘
```

## 4. 分模态技术方案

### 4.1 语音链路（言语表达 + 语音特征异常）

| 步骤 | 选型 | 许可 | 说明 |
|---|---|---|---|
| VAD + 中文 ASR | **FunASR**（SeACo-Paraformer-large，帧级时间戳+热词） | MIT | 中文 CER 显著低于 Whisper；large 约 4-6G 显存，可 CPU |
| 分角色（diarization） | **3D-Speaker / CAM++** 说话人日志 | Apache-2.0 | 双人真实对话 DER≈4.7%，CPU RTF≈0.03，ModelScope 直下无门禁 |
| 轮次对齐 | ASR 时间戳 ∩ 分离片段，按重叠度绑定说话人 | — | 输出 `turns[]`（含真实 diar_confidence） |
| 声学特征 | **parselmouth**（Praat 内核：F0/jitter/shimmer/HNR）+ **librosa**（能量/谱质心/静音段） | GPLv3+ / ISC | 按 eGeMAPS 定义自提核心 6-10 维，**规避 openSMILE 商用禁令** |
| 言语异常检测 | **个体基线 z-score + 滑动窗突变检测** | — | 语速、停顿率、静默占比、F0 变异、jitter 五类；阈值用中文 MODMA 数据集校准，后续叠加 XGBoost 分级 |

方法学依据：抑郁 → 语速/话轮时长下降、停顿增多、F0 下降、jitter/shimmer 升高；焦虑 → 语速加快、音调升高、颤抖（BMC Psychiatry 2024 Meta 分析，DOI 10.1186/s12888-024-06253-6）。

### 4.2 语义链路（话题提取 + 语义影响值 + 矛盾检测）

| 步骤 | 选型 | 许可 |
|---|---|---|
| 话题切分 | 先按说话人轮次切分 → bge-m3 embedding 相似度 + 变化点检测（**BERTopic**） | MIT |
| 影响值建模 | 影响值 = 话题跨度 × 情感极性翻转（SenseVoice 情感标签 / Erlangshen-Sentiment）× 矛盾密度；权重系数回测标定 | 自建 |
| 陈述矛盾初筛 | **Erlangshen-Roberta-330M-NLI**（101 万中文 NLI 样本微调，CPU 可跑，蕴含/矛盾/中立） | Apache-2.0 |
| 对话级 NLI 复核 | Qwen2.5-7B 私有化，长上下文窗口复核 | Apache-2.0 |

输出 `impacts[]`（话题边界/标签/影响值/四维分解），对应需求功能要求第 1 条。

### 4.3 视觉链路（表情 / 姿态 / 手部）

| 目标 | 选型 | 许可 | 口径 |
|---|---|---|---|
| 单人检测跟踪 | SCRFD + ByteTrack | MIT | 离线逐帧，稳定性优先 |
| 面部 AU + 头姿 | **MediaPipe Face Landmarker**（478 点 + 52 blendshape；browDown≈AU4、eyeSquint≈AU7） | Apache-2.0 | 替代 OpenFace 2.0（CMU 商用版税）；皱眉压缩/负性情绪闪现有足够精度 |
| 情绪维度（备选） | HSEmotion（ONNX，CPU 毫秒级） | Apache-2.0 | 作为 AU 之外的第二通道 |
| 身体姿态 | **RTMPose-m**（ONNX，CPU 11ms/人） | Apache-2.0 | 躯干后仰=肩/髋-垂直轴角；身体朝向=肩线法线+扭转角（几何量免训练） |
| 手部自触 | **MediaPipe Hand Landmarker** + 手-脸/手-手关键点距离+速度几何规则 | Apache-2.0 | 搓手/摸脸/自触**无现成商用模型**：几何规则冷启动 → 自标注 100-300 段 → 轻量分类器迭代 |
| 微表情 | AU 强度时序 + 40-500ms 持续门限的「AU 闪现」检测 | — | 学术 SOTA spotting F1 仅 0.41-0.45，**不承诺真正 MER**，与「模型推断+反事实」叙事一致 |

头部回避 = Face Landmarker 头部欧拉角（偏航/俯仰）离开对话中位区间的持续时长。

### 4.4 视频生理（rPPG：心率/HRV）

- **rPPG-Toolbox**（MIT）：POS/CHROM 传统法起步（受控光照 UBFC-rPPG MAE≈1.1 bpm），PhysFormer 深度法为增强项。
- 精度口径：谈话室固定机位 + 均匀光照 + 8s 窗，HR 可达 ±2-5 bpm；**HRV 的 IBI 误差数十毫秒级，LF/HF 只报趋势方向、不报绝对值**——定位趋势通道，非诊断级。
- 质量降级标记：人脸遮挡/大姿态/光照跳变时输出 quality=degraded 并按不可用处理（与原型质量降级口径一致）。

### 4.5 毫米波（文件级真实解析）

- 现有 `mmwave_resp_152s.csv` 链路真实化：重采样 → 0.1-0.6Hz（呼吸）/0.8-2.0Hz（心跳）带通 → 谱峰估计 → RR/HR 序列。
- 基线对比输出 `trend.metrics`（baseline→peak、峰值时刻、末段值、逐点序列），供前端 Spark 趋势线渲染。
- 在线接入契约（预留）：MR60BHA2 级 60GHz 模组（¥300-450）UART → 网关 JSON（1Hz + epoch 时间戳）；静坐 1-2m RR ±1 / HR ±2-5 bpm（Vital-Radio，MIT，CHI'15 学术背书）。
- 口径：说话体动/多目标串扰为主要退化源，结论封顶「相对基线趋势 + 质量降级标记」。

### 4.6 近红外（fNIRS 文件级）

- 需求语境下「近红外」= **fNIRS**（前额叶 HbO/HbR，与认知负荷/情绪相关），非指尖 PPG；保持 `nir_hbo_152s.csv` 现有口径。
- 厂商导出件按修正比尔-朗伯定律（MBLL）转 HbO/HbR 浓度变化，输出多通道均值趋势。
- 在线接入契约（预留）：国产 fNIRS（慧创 NirSmart 级，WiFi + TTL 同步）原始光强流 + MBLL 转换。

## 5. 多模态融合与升级（决策级）

- **对齐**：文件级沿用现有分钟级时基 + `time_base` 显式声明；在线侧统一 NTP 时钟，各采样率重采样到公共 1-10Hz 时轴（fNIRS TTL / 雷达触发帧作硬件锚点）。
- **事件化**：30-60s 滑窗内各模态独立产出 `{ts, 指标, 偏离度, 证据片段}`——没有命中的模态显式显示 ✕（避免「没测」被读成「正常」）。
- **升级规则**（复用原型 E1+E2 判定函数）：主信号 ≥1 且命中模态 ≥2 → ESCALATED；单模态 WARN/ALERT 按偏离度分级；输出逐事件模态贡献清单。
- **模态可用性矩阵沿用**：视频 6 路 / 音频 2 路 / 扩展信号封顶趋势层，矩阵由素材类型自动推导（不由人勾选）。
- 特征级融合（MulT/MMIM 类）作为算法储备在方案中引用，不进实测链路（需标注数据、不可解释、难验收）。

## 6. 可解释心理归因（L1→L2→L3）

- **规则库 YAML 工程化**：规则条目 = `{L2 条件模式（模态+指标+阈值）→ 候选 L3 心理解释 + 文献 DOI + 反事实句 + 免责句}`。引擎只命中不推理，输出「候选解释排序 + 支持/反驳证据 + 反事实」（例：「若仅 HR 升高而言语平稳，则不支持焦虑解释」）——完全确定性、可审计。
- **LLM 角色边界**：Qwen2.5-7B/14B 私有化（Ollama/vLLM，单卡 24G）只做规则命中结果的结构化叙述组装、多规则矛盾分析、报告草稿；**数值与判定一律由代码计算，LLM 不得生成数值**。
- **幻觉控制四件套**：RAG 白名单检索规则库与文献条目 → JSON Mode 强制 `{answer, citations[]}` 结构化输出 → schema 校验 + citation doc_id 回溯校验（引用必须落在检索结果内）→ temperature=0；报告页展示引用原文片段供人工复核。

## 7. WebRTC 采集与处理范式（单链路）

- 前端新增「活体采集」入口：getUserMedia（音视频）→ 本地预览（画面 + 音频电平条 + 计时）→ MediaRecorder 分片（如 10s 片）经 WebSocket/HTTP 流式落盘（WebM/Opus + 自动转 16kHz WAV 与 25fps 帧序列，FFmpeg 服务端转码）。
- 采集结束 → 自动创建导入会话并起批，与文件导入**同一条分析管线、同一份报告口径**（报告强制标注来源：离线导入 / 实时采集转离线分析）。
- 不做实时判定：采集端无风险预警类 UI（那是完整版实时监看链路的范围，精简版明确不含）。

## 8. 工程实现：契约对照与数据模型

### 8.1 服务端点对照（Python 服务须逐条实现）

### 8.3 部署形态

- 单机一体机：RTX 3060/4060 级（16-24G 显存）即可全链路；语音+视觉基础版可纯 CPU 降级运行。
- 任务队列：FastAPI + asyncio worker（前期单worker即可），FFmpeg 与推理进程池隔离；GPU 任务串行排队，进度按真实阶段回报。
- 存储：素材文件 + 中间 artifact（转写文本/AU 时序 CSV/特征表）全量留痕，支撑人工复核与取证。

## 9. 指标口径与合规

- **双轨基线**：首选现场静息标定（入席 3-5 分钟静息段中位数作个体基线）；文献参考水平（如 RR 12-20 次/分）仅作异常区间参照；无标定数据时只出相对升幅、不出绝对结论。
- **非临床声明**：界面/报告/导出三处写死「行为与心理状态辅助分析，不构成临床心理诊断」。
- **数据合规**：生理与音视频数据按《个人信息保护法》敏感个人信息处理——单独同意、加密存储、脱敏导出、审计留痕（沿用现有 audit seq/hash 机制）。

## 10. 验证计划（对齐两类数据源）

### 10.1 文件样例端到端（已有四份对齐样例）

1. 四登记区导入 → 真实起批 → 逐素材分阶段进度（WS）；
2. 结果页核对：转写轮次与真实台词一致、EV 事件时间戳与视频画面对得上、AU/姿态证据片段可回放定位；
3. 毫米波/近红外趋势曲线与 CSV 原始序列肉眼可对；
4. 报告起草→审批→发布全链路真实数据，导出 HTML 附表 A 逐素材列出。

### 10.2 WebRTC 活体采集验证

双人对话 3-5 分钟（含 1 分钟静息标定段）→ 自动起批 → 与文件链路同等核对；重点验证：说话人分离正确率、AU 时序与表情同步、采集-分析自动衔接。

### 10.3 每环节可观测中间产物（实测可出示）

转写 JSON（含时间戳/置信度）→ 声学特征表 CSV → AU 时序 CSV → 姿态角度序列 → rPPG 波形与 HR 序列 → 毫米波/近红外趋势序列 → 规则命中清单 → 归因 JSON（含 citations）。

## 11. 风险与对策

| 风险 | 对策 |

| 微表情检测学术不成熟（F1≈0.41-0.45） | 采用「AU 闪现」口径（40-500ms 门限），不承诺 MER，与推断叙事一致 |
