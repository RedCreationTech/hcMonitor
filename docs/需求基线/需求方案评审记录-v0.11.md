## 1. 评审约定

1. 按用户要求使用 `grill-me`：一次只讨论一个问题，先解决前置决策，再讨论依赖它的分支；能通过代码和资料查明的问题不转交用户猜测。
   - 后续方式变更：用户于本轮明确要求将不影响开发的剩余问题按推荐先记录。本轮起不再对这些问题逐项提问，采用可追溯默认值；此用户指示优先于原逐项访谈方式。
2. 每个问题记录背景、备选、推荐、用户答复、决策、影响范围和后续分支。推荐答案不等于用户已确认，未回答不按同意处理。
3. 已确认决定可通过后续评审变更；保留旧决定、原因和受影响版本，不能无痕覆盖。
4. 方案内 `REQ-xxx / DES-1xx / TASK-1xx / TEST-1xx` 为本轮追溯编号；原 PRD 的 `R/DR/ALG/DS/AT` 和 UI 的 `Pxx/UI.Pxx.xx` 保留原编号。
5. “已确认”仅表示设计决定已确认，不表示代码已实现或验收已通过。当前主任务为需求、方案与评审文档；用户在 Q-005 指示沿用本地编译后，已执行现有代码构建/语法检查，未开始业务代码改造。

- 背景：当前系统支持 HTML 报告和 CSV 事件数据；正式版还需确定是否新增 PDF 或可编辑 Word，关系到模板、离线字体/生成依赖及版本验收。
- 当时推荐：PDF + HTML + CSV；PDF 用于正式归档/分发，保留现有 HTML 和结构化数据，不新增可编辑 Word。
- 当时备选：只保留现有 HTML + CSV；或增加 Word，提供 Word + PDF + HTML + CSV。
- 用户原答：**“PDF＋HTML＋CSV（推荐）：增加正式PDF报告，保留现有HTML和数据导出”**。
- 生效决定：DEC-009，采用推荐方案；不新增可编辑 Word。
- 方案影响：REQ-015/016/026、P09/P18、TASK-110/111/113/116、TEST-115/116/126；格式选择不代替导出/打印权限和审批决定。
- 细化建议：三种输出引用同一报告/分析版本，但各自文件 hash 独立；PDF/HTML 从冻结报告快照渲染，CSV 明确报告证据附件与分析全量数据的不同范围/权限，不能混入别的 run 或借报告阅读权下载全部事件。

### Q-010 首期导出审批粒度

- 状态：**已确认**。
- 依赖：DEC-002 版本报告闭环、DEC-009 PDF/HTML/CSV。
- 背景：完整 UI 的 P18 按项目策略审批，阅读/下载/打印分权。需要明确首期每次导出是否再次人工审批，而不将“报告已发布”自动等同“任何人可下载”。
- 当时推荐：发布时对指定报告版本、接收人、用途、下载/打印动作及有效期授予权限；授权内重复生成/领取仍检查权限、限制并记录日志，不重复人工审批；范围变化重新授权。
- 当时备选：每次下载/打印均单独人工审批，即使接收人和版本相同。
- 用户原答：**“按版本授予权限（推荐）：发布时分别授予阅读/下载/打印，授权有效期内重复导出免再次人工审批”**。
- 生效决定：DEC-010，采用推荐方案。
- 方案影响：REQ-015/016/017、ReportAccessGrant/ExportJob、P09/P18、TASK-110/111、TEST-115/116；M1使用版本授权策略，不保留每次人工待批作为默认必经流程。
- 与原 UI 的差异：M12/M22、UI.P09.05/UI.P18.04 的逐次申请/待批交互在M1调整为权限展示、生成/领取及无权/过期提示；不修改原始设计包，差异在方案保留。生成任务可以异步，授权有效不等于文件ready。
- 细化建议：ReportAccessGrant和ExportJob分开，前者授予资格，后者记录一次文件生成/领取；每次导出有新日志/幂等键，重复授权内导出不自动延长权限，不继承到新版本或新受众。

### Q-011 首期算法验收门槛

- 状态：**按用户委托采用推荐默认值，非逐项答复**。

- 方案影响：REQ-008/010/011/013/014/021/028、DES-108、M1退出条件与TEST-108/110/111/113/114/121/128；真实样本和效果统计仍需具备，缺少样本不能宣称能力验收通过。
