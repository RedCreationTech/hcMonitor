# 暂停录制分段分析方案

## 1. 范围与决策

2026-10-27，用户明确要求：暂停恢复后只排除缺口，其余有效片段继续分析。此项作为DEC-012，增补REQ-007/009/012/013/015，管线版本升为 `m1-2.1`。此前“整份存在未映射缺口则仅转写”的M1限制由以下规则替代，旧版原件、运行和已发布报告不覆盖。

## 2. 新录制：独立连续原件

- 暂停时停止当前MediaRecorder并等待最终数据写入；保留摄像头/麦克风预览和采集租约。恢复时创建新的MediaRecorder，录成另一份完整WebM原件。
- 每段有独立素材ID、分块/全文件SHA256和文件内时轴，逐段封存后统一提交唯一批作业。任务最多12段；到达上限时可结束当前任务，继续录制另建任务。
- capture采用 `independent-segments-v1`，记录每段素材、现场起止、结束原因及暂停/故障事件；服务端校验一一对应、次序和时间范围。现场时间用于采集记录，不用来推算文件秒数。
- 暂停不写入段内连续窗，不计作被访者沉默。转写、声学、话题、视觉和生理通道分别执行，基线/持续时间/同窗融合均不跨段；个人身份、长度、模态和基线质量门仍生效。
- 正常结束的前段不因后续设备故障而失效。故障或异常恢复尾段无法确认连续性时只限制该段；未取得数据的空段有排除记录，不伪造为已封存素材，也不阻止其他有效段交付。

## 3. 旧版合并录制：核验有效文件区间

旧版只记录浏览器现场计时，暂停在封装文件中可能压缩或形成时间戳间断，不能把现场秒数直接用作分析边界。

分析师在“证据工作区 → 暂停 / 故障后的连续有效区间”回看原件，以文件内秒数登记最多12个连续范围，填写核验依据并确认。`POST /v1/sessions/{sid}/analysis-intervals` 校验角色/资源/用途、当前修订、范围次序、时长和原件指纹，保存后修订递增、旧结果过时；用户再“按修订重算”。区间草稿和冲突提示保留，旧run及报告不改写。

运行时在新run工件目录截取派生片段，每个片段独立分析；原件保留。边界跨越的转写、话题和检测事件不进入连续分析；输出时刻映射回原件文件秒数，记录segment_id。未登记的其他素材遵循自身质量规则。未核验的旧版缺口仍保守处理，不自动猜测位置。

## 4. 引用、复核与报告

- 融合按素材、参与者、连续段分别计算；同型合并与升级均不能跨段。派生片段及各通道工件保留指纹，可回溯原件和有效范围。
- 有效区间、核验人/依据、排除范围及逐段质量进入run清单和固定报告附件；话题指数只在连续段内归一，不跨片段比较。
- 事件记录段编号和映射后的原件时刻；新区间报告CSV附segment_id。旧版报告及其冻结可读稿保持原样。
- 区间变化必须新run、新复核和新报告版本，不能把原批准或授权直接沿用到新内容。

浏览器虚拟设备、合成检测夹具、真实本地算法分别记录；工程样例不代替真人效果、真实设备、同步精度或参考量测验收。片段太短、身份未知、个人基线不足、人脸不可见或生理窗口不足时仍会降级，这是逐段质量结论。
