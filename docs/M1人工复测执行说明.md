# M1 人工复测执行说明

## 1. 复测范围与准备

依据《优化完善需求方案设计》v0.11、DEC-001—011。本轮验证M1可用闭环：本地账号与项目分派、逐人用途、导入/录制、批分析、校正与新运行、独立复核、版本报告和授权导出。18页完整产品的研究/盲标/模型审批、跨次比较、在线硬件及3—4人功能仍按C/D/E阶段实施。

首期服务器基线为macOS26.5.1 Intel；其他OS/Apple Silicon未验收。

本机入口：**http://127.0.0.1:5190**。服务未启动时，在 `精简版/analysis-service/` 执行：

```bash
.venv/bin/python manage.py serve
```

该入口会启动本项目自己的PostgreSQL；页面与接口同一地址。开发前端另可在 `prototype-lite/` 执行 `npm run dev`，地址5185；真实模式为默认值。5186的 `npm run dev:mock` 只用于历史模拟回归，不能用来验收真实算法。

账号初始口令位于本机私有文件 `analysis-service/data/m1/initial-credentials.json`（权限600，不入Git）。请分别使用下列账号；登录后可在“账号与项目治理”更换口令。

| 身份 | 工号 | 主要用途 |
|---|---|---|
| 分析师 | W-02 | 导入、转写/角色校正、重算、编制报告 |
| 指定复核人 | R-01 | 逐条行为/解释决定、批准、发布与版本授权 |
| 采集员 | C-04 | 录制/上传并交付给指定分析师 |
| 报告阅读者 | READ-01 | 阅读获授权版本，按授予动作下载/打印 |
| 项目管理员 | A-01 | 任务分派、用途登记、限制和审计；不能直接读业务原件 |
| 审计员 | AUD-01 | 范围内审计与全局链校验，不自动拥有业务读取权限 |

使用不同浏览器配置文件或不同浏览器分别登录各身份。**多个普通标签页、同一浏览器的多个隐身窗口通常共享登录态，不适合扮演不同账号。**

先用演示素材熟悉流程：`prototype-lite/public/demo/` 的音频、视频、近红外/毫米波CSV。它们仅用于工程演练，不作为真人效果验收。实际业务复测须另准备有权使用的成人普通话双人样本、相应文书与人工核对结果；不要把测试草稿写成正式业务判断。

## 2. 推荐执行顺序

### TEST-101—104：账号、用途与完整上传

1. 用未登录窗口直接打开 `/v1/state`，应返回401；输入旧演示口令1234应不能登录真实服务。
2. 用W-02进入“新建导入”，填写项目、对象、场景、告知文书号和两名不同匿名编号。只能登记一名访谈员、一名受访者。
3. 不勾选两人的采集/分析用途，提交应受阻。专家复核、报告用途按实际授权分别登记；训练用途保持关闭。
4. 先添加音频，再添加视频/文件传感器。**明确选择主素材**，不要依靠上传顺序推断。
5. 保存并上传，素材应从“待上传”变为“已封存”。文件名相同也应保留不同素材编号，不覆盖原件。
6. 断网或关闭页面导致上传未完成时，恢复后在任务台对应素材点击“续传该素材”，重新选择**同一原件**。完整文件SHA256绑定原件；不同文件应拒绝续传或覆盖。
7. 尝试在未封存前开始分析，应被阻断；错误格式、少字节、超配置限额应显示失败，不可把“仅登记元数据”当作成功。

记录：任务ID、主素材ID、素材SHA256、错误截图。不要在记录中填写口令。

### TEST-105—107：批作业和录制

1. 完整封存后进入“证据工作区”，点击“开始 / 重试分析”。应出现持久作业ID、状态、阶段及进度；任务台也显示当前阶段。百分比为阶段进度，模型加载或长步骤期间可暂时不变，不能按等待时间虚增；重复请求不能造成同一个在运行版本重复排队。
2. 分析期间刷新页面，作业继续；“请求取消”应停止隔离进程且不生成成功报告。停止/崩溃的进程保留失败或中断原因，重试产生新run。
3. 用“本机录制”填写同样的逐人授权。开始后查看画面、麦克风电平和已用时；暂停、恢复、结束，结束后自动上传封存并只排队一次。
4. 拔设备或拒绝设备权限，应显示故障并保存可恢复片段；上传失败时可重试或下载本地原件。再次登录相同账号可恢复未交付录制；不同账号的正常界面不应展示该缓存。
5. 暂停/设备故障应记录实际时间事件。新录制暂停即封存当前连续原件，恢复另录一段；每段正常分析，不跨暂停计算连续窗口或融合。仅故障尾段等未确认连续性素材保持保守处理。旧版合并录制可在证据工作区回看并登记文件内连续有效区间、核验依据，保存后按修订重算，保留旧run与报告。浏览器本地缓存只是补救手段，请勿清除站点数据；原件封存后才清理该录制缓存。

本机localhost可采集；其他电脑通过局域网采集须使用受信任HTTPS和允许的设备权限。Chrome虚拟设备自动测试不替代现场摄像头/麦克风验收。

### TEST-108—111：角色、文本与话题修订

1. 检查逐句原文、起止时间、匿名声纹编号。初始聚类**不根据发言时长确认身份**；角色未知是可接受的保守状态。
2. 对照原件把明确的轮次分别绑定“访谈员/受访者”；未知、重叠、第三人插话保持未知/重叠，不强行分配。
3. 改一句转写，分割一句，再合并相邻同角色、同素材的轮次；校准时间和文字后保存。分割默认中点，须人工检查。
4. 调整话题标题及边界，保存后应显示旧结果过时，旧run仍可查看。不同素材各用自己的时间轴，不能跨文件套用同一个秒数。
5. 两个W-02配置文件同时打开同一修订：先在甲保存，再在乙保存旧修订，应409并保留乙的本地文字；核对最新版本后再合并。
6. 点击“按修订重算”，应产生新run和新报告版本；此前原文、run、已发布报告及其指纹不被覆盖。重算失败时旧结果不能冒充本次结果。
7. 基线不足或MAD为零时，应显示不足/降级，不得以全程样本或极小分母制造个人偏离。话题指数只作文件内相对排序，不代表心理诊断、因果或跨人可比量表。

### TEST-112—114：证据回看与分层复核

1. 点击轮次、话题和事件时间，播放器应切到正确素材及秒数；检查多个同名文件不会串源。
2. 检查事件的观察、候选规则、来源素材和运行清单；聚合应能追溯到原始事件成员。
3. 以R-01打开任务，逐条选择“行为成立/不成立/弃权”及“支持解释/不支持/弃权”，填写理由。可以行为成立、解释弃权。
4. 趋势封顶、目标未知或行为不成立的条目，不能保存“支持心理解释”。W-02不能充当独立复核人；同自然人多账号也不能自行批准。
5. 核对本地叙述状态：正常样例应有真实生成、当前run/事件/规则引用和模型指纹。无适用证据应明确“不适用”；缺模型、超时或非法输出应明确“降级”，不能伪造生成成功。
6. 近红外/毫米波仅文件趋势，不作心理归因或升级。画面目标身份未可靠绑定时，视觉观察也不进入个人心理解释。有效心率窗口不足时不能显示生理量测可用。

### TEST-115：版本报告与独立批准

1. W-02在“版本报告”核对质量/能力边界、观察、候选叙述与免责，保存编制文字；完整免责原文不能删除。
2. 未完成逐条复核、存在过时来源或未获报告/复核用途时，提交应被阻断。
3. 提交后报告锁定；R-01可带理由驳回，W-02修订后再送审。
4. R-01批准指定内容后，W-02不能直接改写。需“创建新版本”，版本号递增，重新送审、批准。
5. 批准后再次修改证据复核决定，发布应受阻，须另建版本或重新送审，不能沿用旧批准。

### TEST-116：阅读、下载与打印

1. R-01“发布并授予版本权限”，先给READ-01**仅阅读**，选择明确用途与截止时间。
2. READ-01应只见获授权版本；进入阅读自动核验并留痕。下载/打印按钮不可用，直接调用导出接口也应403；不能取得原始媒体。
3. R-01新增同版本的下载/打印授权。READ-01选择相应用途后下载PDF、HTML、CSV，重复下载无需再次人工批准，但每次生成和领取都应留痕。
4. PDF检查中文、分页、页码、免责、接收人/用途、证据复核及指纹；HTML核对相同内容；CSV检查引号、逗号、换行与报告版本/内容hash。
5. 撤销授权或令其到期后，刷新阅读页应失去访问；先前生成文件的旧领取链接也应拒绝新领取。
6. 新版本不会继承旧版授权；扩大用途、人员或动作须新增授权。

系统控制的是应用内阅读、文件生成与领取。已经合法交付的文件、截图或浏览器在系统外的复制/打印不能远程抹除，按单位流程处理，不把这项控制解释成DRM。

### TEST-117/123：限制、审计与恢复

1. A-01在“账号与项目治理”填写理由并限制任务。其他账号的列表/报告、媒体Range、导出和旧领取链接应立即受阻；正在计算的隔离进程会被终止。
2. 解除限制前核对用途依据；需修改用途时先“修订用途登记”，保留旧登记，再单独解除限制。没有原件的历史记录不能因此变成已封存素材。
3. AUD-01校验审计链，核对失败登录、上传封存、排队、修订、复核、批准、发布、授权/撤销、导出/领取和限制记录。
4. 备份恢复必须在专用副本演练，**不要向当前业务库覆盖恢复**：

```bash
# 在 analysis-service/；等待当前作业结束，并停止新任务。
.venv/bin/python manage.py backup --path /一个不存在的绝对路径/M1备份
# 恢复目标须为全新的工作区。此处显式留空数据库URL，仅用于独立SQLite恢复演练。
DATABASE_URL='' DATA_ROOT=/另一个不存在的绝对路径/M1恢复演练 .venv/bin/python manage.py restore --path /上述绝对路径/M1备份
DATABASE_URL='' DATA_ROOT=/上述恢复演练路径 .venv/bin/python manage.py verify
```

5. 核对原件、工件、报告指纹和审计；恢复不保留旧登录token。备份后的用途限制应将相应限制记录带入恢复核验流程，不能凭恢复旧备份重新授予用途。

## 3. 离线安装复测

本机已准备完整离线目录 `analysis-service/data/offline-delivery-final/`：Intel macOS Python、PostgreSQL、ffmpeg/ffprobe、固定141个依赖wheel、模型、字体和编译后的UI。它不含当前业务库、当前账号口令或上传原件。

1. 复制整个目录到新的目标位置/目标Mac；保留执行权限。先核对交付清单和包指纹，断开互联网，局域网保留。
2. 在新的副本执行 `./install.command`。安装检查文件hash，以 `--no-index --require-hashes` 安装依赖，初始化独立数据库和随机口令。已有运行配置时拒绝覆盖。
3. 执行 `./start.command`，使用该副本账号文件登录，导入包内 `fixtures/demo-audio.m4a`，完整执行分析、修订、复核、发布及PDF/HTML/CSV领取。
4. 完全停止并重启，核对冷启动不下载模型；缺失/变更固定模型文件应拒绝，不可回退模拟或公网。
5. 局域网多人测试配置单位证书后，再设置 `BIND_HOST=0.0.0.0`、`TLS_CERT_FILE`、`TLS_KEY_FILE` 和 `COOKIE_SECURE=1`。验证多客户端、WebSocket重连、媒体Range、授权撤回及实际设备权限。

同一Mac上的迁移目录、全新虚拟环境验证已有自动化记录；**全新物理系统、单位证书/多电脑环境仍须按本节实测**。

## 6. 暂停分段增强复测（2026-10-27）

1. 新录制先持续一段、暂停、恢复并录第二段后结束：应出现两份独立已封存素材，统一起批；每段均有自己的质量结果，不再因暂停整体退回仅转写。
2. 暂停后直接结束：只交付已有完整片段，不新增空尾段；最多12段，达到上限应结束当前任务后另建任务。
3. 分别验证首段、末段上传中断后刷新，再打开“本机录制”重试交付：前段不覆盖，后段续传，各段原件都可单独下载。
4. 对旧合并录制先回看原件，在“暂停 / 故障后的连续有效区间”按播放器文件秒数登记范围，不能照搬含暂停的现场计时；勾选核验并填写依据后保存，再按修订重算。
5. 检查区间之外及跨缺口证据被排除；基线、话题和连续指标不跨段，事件仍能跳转到原件正确秒数。检查固定报告附件、核验人/依据、原件/派生工件指纹与CSV段编号。
6. 短片段、身份/个人基线不足、无画面/心率有效窗时仍应按段降级；不要把“继续分析”理解为所有模态均已可用或效果已达标。
